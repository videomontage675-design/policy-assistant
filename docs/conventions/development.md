# إرشادات التطوير

- الغرض: كود بسيط وقابل للاختبار والصيانة من مطوّر واحد.
- الجمهور: كل من يكتب كوداً أو اختباراً في المشروع.
- آخر تحديث: قبل المرحلة 1.

## المبادئ
1. البساطة أولاً (KISS / YAGNI): أبسط حل يحقق المتطلبات [الأساسية]. لا طبقة تجريد ولا مكتبة «للمستقبل».
2. لا تقنية دون ADR: اللغة وإطار العمل وقاعدة البيانات ونموذج الذكاء الاصطناعي تُحدَّد في ADR معتمد قبل استخدامها.
3. فصل المسؤوليات: كل وحدة مسؤولة عن شيء واحد. الوحدات المتوقعة: ingestion (استيعاب الوثائق)، retrieval (الاسترجاع)، generation (توليد الإجابة)، logging (التسجيل الداخلي)، admin (الإدارة)، api (الواجهة). الأسماء النهائية تُحدَّد في ADR.
4. الإعدادات خارج الكود: كل ما يتغير بين البيئات أو يعدّله المالك (النموذج، الحدود، الرسائل) يوضع في ملفات إعداد أو قاعدة البيانات، لا في الكود.
5. الفشل الآمن: عند أي خطأ في الاسترجاع أو التوليد، يعود المساعد برسالة عدم التوفر والتحويل (FR-06)، لا بإجابة مخمَّنة.

## الأسرار والخصوصية
- المفاتيح وكلمات المرور في متغيرات بيئة فقط. احتفظ بملف `.env.example` بأسماء المتغيرات دون قيم، وأضف `.env` إلى `.gitignore`.
- لا تسجّل في السجلات: أرقام الهواتف، البريد الإلكتروني، العناوين، أرقام الطلبات الكاملة. أخفِها قبل الحفظ (Privacy).
- الاختبارات ببيانات وهمية فقط.

## الاختبارات
- كل دالة فيها منطق لها اختبار وحدة (unit test).
- لكل متطلب وظيفي [أساسي] اختبار واحد على الأقل يذكر معرّفه في اسمه، مثل `test_fr07_country_specific_policy`.
- جودة الإجابات تُقاس بمجموعة التقييم في `evals/`، لا باختبارات الوحدة وحدها.
- لا تُسلَّم مرحلة وفيها اختبار فاشل.

## جودة الكود
- أسماء إنجليزية واضحة، بلا اختصارات غامضة.
- أداة التنسيق والفحص (formatter / linter) تُحدَّد في ADR التقنية، وتُشغَّل قبل كل commit.
- دوال قصيرة. التعليق يشرح «لماذا» لا «ماذا»؛ إذا احتاجت الدالة تعليقاً لتشرح ماذا تفعل، فقسّمها أو أعد تسميتها.
- ثبّت إصدارات الاعتماديات (dependencies)، ولا تضف اعتمادية جديدة إلا بمبرر في رسالة الـ commit أو في ADR.

## Git
- لا تعمل على `main` مباشرة؛ اعمل في فرع منفصل.
- رسائل commit بصيغة Conventional Commits، مع معرّف المتطلب عند وجوده:
  - `feat(retrieval): filter chunks by country (FR-07)`
  - `docs(adr): add ADR-001 architecture decision`
  - `test(generation): cover no-answer fallback (FR-06)`
- commit صغير لكل تغيير منطقي واحد.

## التسجيل (Logging)
- سجل منظم (JSON) لكل سؤال: معرّف المحادثة، الوقت، البلد، الفئة، الوثائق والأقسام والإصدارات المسترجعة، زمن الاستجابة، وهل حُوِّل السؤال (FR-05، FR-13، FR-14).
- المستويات: INFO للمسار الطبيعي، WARNING لعدم وجود إجابة، ERROR للأعطال.
